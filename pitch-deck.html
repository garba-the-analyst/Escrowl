01 · Problem

Freelance payments fail on trust

  • Buyers fear paying upfront and getting ghosted.
  • Sellers fear delivering and never getting paid.
  • Existing escrows freeze funds when anyone disappears — seller vanishes, arbiter ghosts, money locks forever.
  • In African P2P markets this friction kills deals daily.
02 · Solution

Escrow as a reusable trust primitive

  • Milestone vaults — buyer funds once, releases per deliverable, 2.5% protocol fee.
  • Single designated arbiter — exact-sum dispute splits, fee only on the seller leg.
  • Liveness exits — stale milestones reclaimable, abandoned disputes expire 50/50. No permanent lock exists.
  • SPL classic only — Token-2022 extension risk rejected by design.
03 · How it works

State machine, enforced on-chain

Created —fund→ Funded —submit→ Submitted —approve/timeout→ Released │ └dispute→ Disputed —resolve→ Resolved │ └expire(30d)→ Resolved 50/50 └stale(wait deadline)→ Refunded (buyer reclaim) Pause blocks create/fund ONLY — exits can never be trapped.
04 · Security

Audited like we mean it

  • 12 invariants — vault==locked, terminal-once, exact splits, floor fee + snapshots, conservation on every instruction.
  • Threat model + trust assumptions written down, each row naming its proving test.
  • Checked math everywhere, no unwrap, no unsafe, distinct buyer/seller/arbiter.

07 · Why it wins

Built for the rubric

  • Complexity + clarity — real custody surface (vaults, fees, disputes, timeouts) in a readable state machine with docs an auditor can navigate.
  • Technical readiness — pinned toolchains, committed lockfile, CI that fails on warnings, reproducible builds.
  • Ecosystem impact — a reusable primitive for marketplaces and P2P commerce, starting where payment-trust friction is highest.
